# 多井联合标定 α / 预测新井效率可执行方案

## 1. 目标定义

本方案的目标不是直接训练一个黑箱回归器，而是分两步完成：

1. **先补齐多井统一标签与统一特征库**；
2. **再建立“多井联合标定 α / 新井预测效率”的低自由度校准模型**。

最终交付物应包括：

- 统一数据表；
- 多井标签表；
- 分层校准脚本；
- 留一井验证脚本（前提是标签补齐）；
- 新井预测模板。

## 2. 当前可执行的总体路线

### 阶段A：数据整理与标签补齐

#### A1. 建立 6 井统一数据字典

建议数据表结构：

| 字段组 | 示例字段 |
|---|---|
| well_id | `hu101`, `hu102`, `hu103`, `hutan1`, `hutan2`, `hutan1_002` |
| source_path | 原始文件夹路径 |
| geometry | 井深、井径、套管外径、封固段、井斜 |
| slurry | 浆体密度、流变、失水、强度、稠化时间 |
| spacer | 隔离液密度、流变、冲洗效率、相容性 |
| operations | 排量、替浆量、碰压、泵压、返浆 |
| anomalies | 悬挂器失败、漏失、异常井段、返高偏差 |
| label_numeric | CBL合格率或标准化质量分 |
| label_ordinal | 优/中/差 |
| label_source | 测井评价图 / 技术总结 / 施工评价表 |
| label_confidence | `high / medium / low` |

#### A2. 补齐统一质量标签

目标是给 6 口井中的每一口井至少生成以下之一：

1. **优先**：数值型 CBL/VDL 质量标签；
2. **次优**：可标准化成 0–100 的分段/井级质量分；
3. **最低限度**：有序等级标签（优 / 中 / 差）。

建议顺序：

1. 呼103：优先查固井质量测井评价图或总结中的明确结论。
2. 呼探1：从两份 PDF 和总结中继续找是否存在“合格率/优质率/井段评价比例”。
3. 呼探2：优先找施工总结、测井评价图、固井质量报告。
4. 呼探1-002：优先找测井评价图、施工评价、完井总结。

#### A3. 标签标准化口径

若不同井标签来源不同，建议按以下优先级归一：

1. `bond_qualification_rate_pct`
2. `target_interval_quality_score_0_100`
3. `well_quality_grade`

其中：

- 若仅有“优/中/差”，可临时映射为 `90 / 70 / 40` 之类的工程分数，**但必须单独标记为弱监督标签，不能与真实 CBL 合格率等价使用**。

## 3. 建模方案设计

### 3.1 模型目标

建立两个层次的输出：

#### 模型1：`α` 标定模型

目标：预测每口井的有效校准系数 `α`。

定义：

```text
alpha = (1 - η_field / η_hyd) / S
```

其中：

- `η_field`：现场最终质量标签（数值口径）
- `η_hyd`：模型水动力效率
- `S`：原始惩罚和，如 `w_ch*I_ch + w_mix*I_mix + w_inst*I_inst`

前提：

- 该井必须已有 `η_field` 与 `η_hyd`。

#### 模型2：新井最终效率预测模型

目标：预测新井的：

```text
η_quality_pred = η_hyd_pred × clip(1 - alpha_pred × S_pred, 0, 1)
```

也就是说，优先预测 `alpha_pred` 或 `η_field / η_hyd`，而不是直接黑箱预测 `η_quality`。

### 3.2 推荐模型结构

#### 方案A：最低风险方案（推荐起步）

**物理模型 + 正则化回归**

输入特征：

- 井段长度
- 最大井斜
- 井眼/套管间隙指标
- 领浆/尾浆密度
- 关键流变参数（PV、YP、`n`、`K`）
- 排量与替浆量
- 隔离液密度/冲洗效率
- 是否存在悬挂器失败、漏失等异常

回归目标：

- `alpha`
或
- `quality_ratio = η_field / η_hyd`

模型选择：

- Ridge 回归
- Lasso 回归
- ElasticNet

理由：

- 样本小；
- 易解释；
- 能控制过拟合；
- 便于和物理机理对齐。

#### 方案B：层级方案（标签补齐后）

**分层/贝叶斯校准模型**

结构示意：

```text
alpha_i ~ Normal(mu_i, sigma)
mu_i = β0 + β1*x1_i + β2*x2_i + ... + βk*xk_i + group_effect
```

适用场景：

- 井之间存在明显分组，例如“有/无实测caliper”“尾管/回接”“有/无异常事件”；
- 需要同时表达参数不确定性与组间差异。

### 3.3 明确禁止的做法

1. 不能把同一井的深度点随机切开做训练/验证，伪装成跨井泛化。
2. 不能把定性标签直接等同于 CBL 合格率。
3. 不能在只有 2 口强标签井时训练高维机器学习模型。
4. 不能用单口井 `α` 平均值直接作为通用 `α` 外推全部新井。

## 4. 验证方案

### 4.1 当前阶段（标签不齐）

当前只做三类验证：

1. **呼101 ↔ 呼102 互校验**
   - 检查不同井间 `α` 与 `η_field / η_hyd` 的数量级差异。
2. **弱标签排序验证**
   - 若呼探1被评价为“优”，则其预测质量应高于明确“不合格”井。
3. **情景合理性验证**
   - 高排量、高异常、差冲洗效率的井，不应被预测为更优。

### 4.2 标签补齐后的正式阶段

当 6 口井都有统一数值标签后，采用：

#### Leave-One-Well-Out（LOOW）

共 6 轮：

- 每轮用 5 口井训练；
- 留 1 口井验证；
- 汇总 MAE / RMSE / 排序一致性 / 误差区间。

#### 评价指标建议

- `MAE(alpha)`
- `MAE(η_quality)`
- `RMSE(η_quality)`
- `Spearman rank correlation`
- 异常井识别准确率

### 4.3 何时可以声称“模型准确性已验证”

至少同时满足：

1. 6 口井标签口径统一；
2. 留一井验证完成；
3. 各轮误差稳定，没有某一口井单独把误差拉爆；
4. 新井预测结果与工程判断方向一致。

## 6. 推荐实施步骤

### 第一步：补标签

- 逐井抽取最终质量标签；
- 标记标签类型：`numeric / ordinal / qualitative`；
- 标记可信度：`high / medium / low`。

### 第二步：统一特征

- 把 6 口井统一成一张特征表；
- 缺失值保留，不要随意硬填；
- 对“异常事件”做二元字段，例如 `hanger_failure = 1/0`。

### 第三步：先做物理派生量

逐井计算：

- `η_hyd`
- `S`
- `quality_ratio = η_field / η_hyd`
- `alpha`

### 第四步：先拟合低自由度模型

按以下顺序尝试：

1. 规则模型（按异常事件分层）
2. Ridge / Lasso 回归
3. 层级贝叶斯模型

### 第五步：最后再做留一井验证

只有在 6 井都有统一数值标签时，才正式跑 LOOW 验证。

## 7. 当前阶段的明确产出定义

在当前数据状态下，最现实的产出是：

1. **一个多井联合标定框架**；
2. **一个统一数据字典与字段体系**；
3. **一个弱监督 + 强监督混合建模方案**；
4. **一个等待补齐标签后即可直接落地的 LOOW 验证流程**。

## 8. 一句话执行建议

**先补齐 4 口井的统一质量标签，再做 6井 leave-one-well-out；在此之前，只建议做多井分层校准原型，不建议宣称已经完成可靠的新井精确预测模型。**
