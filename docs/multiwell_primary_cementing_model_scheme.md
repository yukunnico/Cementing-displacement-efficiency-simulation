# 多井通用固井顶替效率模型技术方案

## 1. 文档目的

本文档定义一个面向多井复用的固井顶替效率建模方案。该方案的目标不是只服务呼102井，而是形成一个可配置、可扩展、可校验的模型体系：后续只需更换井筒资料、流体体系和施工程序，即可复用于其他井的固井顶替计算。

本文档同时约束模型边界、模块拆分、输入输出规范、验证方式和分阶段实施路径，作为后续代码重构与开发的统一依据。

---

## 2. 建模目标

### 2.1 总体目标

建立一个**多井通用的分层固井顶替模拟器**，能够：

1. 贴合现场实际施工流程，从**地面开泵**开始模拟；
2. 描述流体从地面进入套管、沿套管内下行、经鞋口进入环空、在环空中顶替钻井液并向上返出的全过程；
3. 输出施工过程中的**实时顶替效率**与施工结束后的**最终水泥浆顶替效率**；
4. 在需要时考虑**套管内流体混合**对鞋口入环空边界的影响；
5. 对不同井型、不同流体体系、不同施工程序保持可替换、可复用。

### 2.2 核心输出目标

模型至少需要稳定输出以下两类结果：

#### A. 水力学核心结果

- 全井段实时有效顶替效率；
- 指定评价井段实时有效顶替效率；
- 宽边 / 中线 / 窄边实时前缘位置；
- 实时窜槽指数、混浆指数、失稳指数；
- 最终全井段水泥浆有效顶替效率；
- 最终目标层段 / CBL井段水泥浆有效顶替效率；
- 最终残余泥浆分布与水泥占据分布。

#### B. 工程解释结果

- 与 CBL / 胶结质量可对照的质量响应指标；
- 风险井段识别；
- 施工程序敏感性分析结果；
- 模拟结果与现场资料的偏差诊断。

### 2.3 成功标准

当模型满足以下条件时，可视为达到阶段性成功：

1. 对呼102井，能够复现现有环空模型主要趋势，并输出从地面开泵开始的全流程结果；
2. 对第二口井，只通过更换输入数据包即可运行，不需要复制或重写求解器；
3. 能够清晰区分：
   - 直接由流体力学计算得到的结果；
   - 基于 CBL 或现场质量资料映射得到的解释层结果；
4. 具备明确的质量守恒、时间推进稳定性和井段对比验证机制。

## 3. 当前模型基础与问题定位

### 3.1 当前项目基础

当前项目已经具备以下基础能力：

- `cemdisp/` 项目骨架；
- 若干经验/判别模型；
- 单井脚本化的 2D 环空顶替求解；
- 顶替效率、质量响应效率、图表与摘要输出流程。

`README.md` 已明确当前项目目标是逐步从旧脚本迁移到统一 Python 项目结构，优先实现“统一变量命名、统一单位、解耦数据与脚本”。

### 3.2 当前 Hu102 模型的边界

现有 `hu102_tail_d2dga_model.py` 明确说明：

> 当前边界条件给的是 **s=0 处的环空入口边界，不是地面泵入口**。

这意味着当前 Hu102 模型：

- 已经具备环空内二维顶替能力；
- 但没有模拟地面开泵到鞋口出流的上游过程；
- 平衡液、隔离液、领浆在当前实现中被折算为瞬时通过或初始切换；
- 套管内可能发生的输运延迟、前缘传播和混合对鞋口边界的影响尚未纳入。

### 3.3 本次方案的核心改进方向

本次方案不推翻现有环空二维模型，而是：

> 在其前面增加一个“地面泵注 → 套管内输运 → 鞋口出流”的上游模块，形成分层耦合架构。

## 4. 总体架构

## 4.1 架构原则

整个模型体系采用**分层解耦**策略：

```text
地面施工程序层
    ↓
套管内 1D 输运层
    ↓
鞋口出流边界桥接层
    ↓
环空 2D 顶替核心层
    ↓
效率诊断层
    ↓
质量解释与报告层
```

### 原则 1：保留现有环空求解器价值

环空二维顶替仍然是整个体系的核心。当前 Hu102 脚本中的二维方位-轴向顶替能力、壁面泥饼清除、窜槽/混浆/失稳诊断逻辑都应优先泛化，而不是被重写掉。

### 原则 2：上游新增模块不能反向污染核心层

套管内输运层的职责是生成“鞋口真实出流边界”，而不是把环空求解器和施工计划硬耦合在一起。这样后续即便只做环空入口研究，也仍可单独调用环空层。

### 原则 3：MVP 不做完整 CFD

首版不追求三维 CFD，也不引入完整压力耦合、非等温、固液沉降全物理闭环。优先实现可复算、可校验、可复用的工程级降阶模型。

---

## 5. 分层模型设计

### 5.1 地面施工程序层

该层负责表达现场真实注入过程。

#### 输入内容

- 每段流体名称；
- 每段注入体积；
- 每段地面排量；
- 切换时刻；
- 停泵 / 续泵信息；
- 替浆程序；
- 现场备注（碰压、胶塞、返高、异常事件等）。

#### 目标

把现场“施工记录”转换为结构化的**地面泵注时间序列**，作为全流程模拟的最上游输入。

### 5.2 套管内 1D 输运层

该层新增，是本方案的关键扩展。

#### 建模目标

从地面开泵开始，模拟流体沿套管内下行，并在任意时刻给出鞋口处的出流状态：

- 当前出流的主导流体；
- 出流体积分数；
- 界面前缘位置；
- 是否已发生明显混合；
- 实时出流排量。

#### 分级能力设计

##### 模式 A：纯输运延迟模式

- 只做容积追踪；
- 不考虑管内混合；
- 适合数据少、先做快速复用。

##### 模式 B：1D 对流前缘追踪模式

- 以套管内一维对流为主；
- 能追踪不同流体段塞前缘；
- 允许施工切换在鞋口处产生真实延时；
- 建议作为默认模式。

##### 模式 C：1D 对流-弥散模式

- 当套管内明显混合会实质影响环空顶替效率时启用；
- 在 1D 对流基础上增加轴向弥散；
- 用于修正鞋口边界纯度。

#### 建议策略

MVP 先落地 **模式 B**，并预留模式 C 接口。

### 5.3 鞋口出流边界桥接层

该层的职责是把“套管内输出”变成“环空入口边界”。

桥接层输出给环空模型的最小接口应为：

- 时间 `t`；
- 鞋口总排量 `q(t)`；
- 各流体在鞋口的体积分数向量 `vec(t)`；
- 当前施工阶段标识 `stage(t)`。

这层相当于替代当前 Hu102 脚本中的 `boundary_state()` 硬编码逻辑。

### 5.4 环空 2D 顶替核心层

这是现有项目最有价值的层，建议保留其核心思想并泛化为多井通用求解器。

#### 核心职责

- 建立偏心环空方位-轴向二维网格；
- 计算轴向流速与周向流速；
- 计算多流体在环空中的对流-扩散输运；
- 计算宽边 / 窄边推进差异；
- 计算壁面泥饼清除；
- 计算水泥浆有效占据和有效顶替效率。

#### 环空层重点保留内容

- 偏心环空几何展开；
- 多流体体积分数输运；
- 浮力增强；
- 窄边抑制；
- 泥饼清除；
- 窜槽/混浆/失稳指标。

#### 环空层应剥离的内容

- 单井硬编码井深；
- 单井固定施工量；
- 单井写死的评价井段；
- 直接从地面程序硬编码映射到环空入口的逻辑。

### 5.5 效率诊断层

该层把场变量转化为可解释指标。

#### 实时指标

- 全井段实时有效顶替效率；
- 指定井段实时有效顶替效率；
- 实时水泥浆占据率；
- 宽边 / 中线 / 窄边前缘推进；
- 实时窜槽指数、混浆指数、失稳指数。

#### 最终指标

- 全井段最终有效顶替效率；
- CBL井段最终有效顶替效率；
- 目标层段最终有效顶替效率；
- 最终水泥浆占据率；
- 最终残余泥浆体积分布。

### 5.6 质量解释与报告层

这一层不再与纯顶替结果混写。

#### 两类输出必须分离

##### A. 水力学直接输出

- 由输运与流动计算直接得到；
- 可作为“模型硬输出”。

##### B. 质量解释输出

- 基于 CBL / 现场质量资料映射；
- 用于工程解释，不等同于流体力学真值；
- 必须显式标记为 `quality_proxy` 或同类命名。

## 6. 可复用数据模型设计

为保证后续换井可复用，建议统一成以下数据结构。

### 6.1 井筒数据 `WellSpec`

建议字段：

- `well_name`
- `top_md_m`
- `bottom_md_m`
- `casing_id_mm`
- `liner_od_mm`
- `liner_id_mm`
- `shoe_md_m`
- `hanger_md_m`
- `hole_diameter_profile`
- `inclination_profile`
- `standoff_profile`（可选实测或代理）
- `evaluation_windows`
- `reference_data_paths`

### 6.2 流体定义 `FluidSpec`

建议字段：

- `name`
- `role`（mud / wash / spacer / lead / tail / displacement）
- `density`
- `rheology_model`
- `plastic_viscosity`
- `yield_stress`
- `power_law_n`
- `consistency_k`
- `temperature_model`（后期可选）

### 6.3 施工程序 `PumpingSchedule`

建议字段：

- `step_name`
- `fluid_name`
- `volume_m3`
- `rate_m3_min`
- `start_time_s`
- `end_time_s`
- `boundary_mode`
- `remarks`

### 6.4 评价窗口 `EvaluationWindow`

建议支持任意数量窗口，例如：

- CBL评价段；
- 目标产层段；
- 油气水敏感层；
- 异常风险段；
- 套管鞋附近重点段。

### 6.5 校验数据 `ValidationData`

建议字段：

- `cbl_profile`
- `cbl_summary`
- `job_report`
- `pump_pressure_series`（若有）
- `returns_report`
- `cement_top`
- `post_job_notes`

## 7. 关键建模假设

### 7.1 当前必须接受的假设

1. 套管内主流动可先近似为一维输运；
2. MVP 阶段不建立全井 CFD；
3. 套管内混合是否要显式加入，以其对鞋口出流纯度的影响是否显著为判据；
4. 环空顶替仍然是顶替效率计算的核心求解域；
5. CBL 资料用于解释与映射，不作为顶替效率的严格真值。

### 7.2 何时必须启用套管内混合模型

若满足以下任一条件，应启用模式 C（1D 对流-弥散）：

1. 不同流体段在鞋口处存在较长重叠混合时间；
2. 前置液 / 隔离液 / 领浆体积较小，界面扩散将明显改变入环空边界；
3. 现场存在明显排量波动、停泵 / 续泵、长时间等待；
4. 高温、长套管内路径、长时程输运使界面退化不可忽略；
5. 通过对比发现“纯段塞假设”与现场结果偏差持续系统性放大。

## 8. 关键效率口径定义

### 8.1 实时有效顶替效率

实时有效顶替效率定义为：

- 当前时刻，水泥浆在评价域中的有效占据程度；
- 若使用泥饼修正，则按 `水泥浆浓度 × (1 - 壁面泥饼残余率)` 计算。

### 8.2 最终水泥浆顶替效率

定义为施工结束（或设定终止时刻）后，水泥浆在指定井段内的最终有效占据水平。

### 8.3 质量响应效率

质量响应效率是解释层指标，应明确区别于“顶替效率”。

建议统一命名为：

- `effective_displacement_efficiency`：有效顶替效率；
- `cement_quality_proxy`：质量响应效率或胶结质量代理值。

## 9. 验证方案

## 9.1 数值验证

每一层都必须通过基础验证。

### 套管内 1D 输运层

- 体积守恒；
- 界面传播时序正确；
- 排量切换响应正确；
- 与解析容积追踪结果一致。

### 环空 2D 层

- 质量守恒；
- 网格敏感性；
- 时间步长敏感性；
- 边界切换稳定性；
- 入口耦合一致性。

## 9.2 物理趋势验证

至少检查以下趋势是否合理：

- 排量升高时，前缘推进速度提升；
- 偏心度增大时，宽边/窄边差异增大；
- 套管内混合增强时，鞋口纯流体边界被削弱；
- 流变增强时，界面稳定性和窜槽行为按预期变化；
- 目标层段局部几何恶化时，局部顶替效率下降。

## 9.3 工程验证

建议按三层推进：

1. 呼102 单井复现验证；
2. 第二口井交叉验证；
3. 多井联合校验与质量映射回归。

## 10. 分阶段实施策略

### Phase 0：输入口径统一

建立统一数据模型和样例井数据包。

### Phase 1：环空 2D 核心泛化

将 Hu102 单井脚本重构为多井可配置求解器。

### Phase 2：套管内 1D 输运层接入

实现从地面开泵到鞋口出流的动态边界生成。

### Phase 3：套管内混合扩展

在必要时加入 1D 对流-弥散。

### Phase 4：质量映射与现场资料对比增强

完善 CBL / 胶结质量代理层。

### Phase 5：多井批量运行与统一报告

形成可切换井数据包的一键运行工具。

---

## 11. 方案边界

本方案明确不在 MVP 阶段包含以下内容：

- 全三维 CFD；
- 完整泵压/ECD耦合；
- 非等温全耦合；
- 固液沉降与凝胶化全机理；
- 全多相复杂井口设备模型。

这些能力可作为后续高级扩展项，但不应阻塞首版多井通用模型落地。

---

## 12. 推荐结论

对于当前项目，最优路径不是继续堆单井脚本，也不是直接跳到重型 CFD，而是建设一个：

> **“地面施工程序 + 套管内 1D 输运 + 环空 2D 顶替核心 + 质量解释层”**

的分层模型体系。

该方案既能贴合呼102现场流程，又能通过更换井资料扩展到其他井，同时能明确区分“流体力学直接结果”和“工程质量解释结果”。

这是当前项目从“单井脚本”走向“多井复用模型平台”的最稳妥路线。
