# 0708资料到模型输入字段映射设计

## 1. 背景

本项目正在从“单井脚本”演进为“多井可复用的固井顶替效率模型”。当前代码侧已经具备：

- 通用数据结构：`WellSpec`、`FluidSpec`、`PumpingSchedule`、`ValidationData`
- 通用求解层：`cemdisp/transport1d/` 与 `cemdisp/models2d/`
- 逐井 loader / runner：呼101、呼102、呼103、呼探1、呼探1-001、呼探1-002

当前瓶颈不在求解器本身，而在资料治理：`D:\users\desktop\research\控压固井项目\0708` 中已经积累了大量 PDF、图片、Word、Excel、施工曲线与导出汇总，但这些资料尚未形成稳定的“原始证据 → 结构化字段 → 参考文档 → loader 输入”链路。

本设计文档用于定义这条链路，重点把 0708 资料规划到**字段映射层**，而不是直接展开逐井代码实施。

---

## 2. 本轮目标与非目标

### 2.1 本轮目标

本轮规划做到以下 5 件事即算完成：

1. 定义 `0708` 资料如何分流到四类模型输入：`WellSpec`、`FluidSpec`、`PumpingSchedule`、`ValidationData`
2. 定义字段提取的证据等级与置信口径
3. 定义 `参考文档/` 的中间沉淀结构与提取数据模板方向
4. 列出当前已具备字段、缺失字段与 fallback 顺序
5. 给出后续实施优先级，但仅到“先补什么字段、再补什么井”的层级

### 2.2 本轮非目标

本轮**不**做以下工作：

- 不直接修改 `cemdisp` 求解器或新增通用 runner
- 不直接实现逐井 loader 重构
- 不全面清洗 `参考文档/` 中所有历史井资料
- 不把低置信度图片识别结果直接写成模型主输入
- 不把 CBL 合格率当作顶替效率真值反向校准模型

## 4. 总体设计：四层资料流水线

本轮采用如下标准流水线：

```text
原始资料包（0708）
  → 证据化提取层
  → 标准字段映射层
  → 参考文档沉淀层
  → 后续 loader 接入层
```

### 4.1 原始资料包层

输入包括但不限于：

- PDF：CBL/VDL 图、技术图、完井报告
- 图片：目录图、结构图、评价图截图
- Word / Docx：施工设计、作业史、实验报告、技术总结
- Excel / Xlsm：套管数据表、施工曲线、汇总表、实验数据表

这一层只保存事实来源，不承担字段标准化职责。

### 4.2 证据化提取层

这一层负责把“文件中的事实”抽成结构化条目。每个条目都必须带：

- 字段名称
- 字段值
- 单位
- 适用井号
- 适用作业阶段
- 来源文件
- 页码 / 图号 / 表号 / 行号
- 证据等级
- 备注

这里的输出不是最终 loader，而是“可以被复核的提取事实表”。

### 4.3 标准字段映射层

这一层负责把证据条目归并到四类模型输入对象：

- `WellSpec`
- `FluidSpec`
- `PumpingSchedule`
- `ValidationData`

映射时只做“字段归属与单位统一”，不掺入求解器特有逻辑。

### 4.4 参考文档沉淀层

这一层把结构化条目落到 `参考文档/<井号>/提取数据/`。它是后续 loader 的稳定中间输入，而不是原始材料的简单复制。

### 4.5 后续 loader 接入层

后续代码实施时，loader 应优先从 `参考文档/<井号>/提取数据/` 读取已确认字段，再映射为 `cemdisp` 的 dataclass 对象。这样可以避免每次修改 loader 都重新翻原始资料。

## 5. 证据等级与字段置信口径

### 5.1 证据等级定义

为避免 OCR、图片识别、导出汇总和原始报告混为同一可信度，字段证据统一分为三档：

| 等级 | 含义 | 使用原则 |
|---|---|---|
| A | 原始正文、原始表格、原始实验报告、原始施工设计中明确给出的数值或结论 | 可直接作为模型主输入 |
| B | PDF 图头、图片可读文本、二次汇总表、导出 CSV、人工转录文本 | 可用于补充与校验，但必须保留来源说明 |
| C | 邻井类比、历史脚本硬编码、文献 fallback、低清图片推断 | 只能在缺失时兜底，不可默认覆盖 A/B |

### 5.2 证据使用规则

1. A 级永远优先于 B、C 级
2. B 级不能覆盖已存在的 A 级
3. C 级只能在字段缺失时兜底，且必须显式标记
4. 来自图片识别的结论若无法映射到明确页码或图号，只能作为 B/C 级备注，不能直接入主字段
5. `质量代理指标` 与 `顶替效率真值` 必须分开保存，不能因为 CBL 图“合格”就反向推导为高顶替效率

## 6. 四类模型输入对象的字段映射口径

### 6.1 `WellSpec` 映射口径

`WellSpec` 负责表达井身结构、井段边界和评价窗口。建议字段来源如下：

| 字段类别 | 典型字段 | 主来源 | 备注 |
|---|---|---|---|
| 井基础信息 | `well_name`, `top_md_m`, `bottom_md_m`, `shoe_depth` | 套管数据表、完井报告 | 优先 A 级表格 |
| 套管程序 | 表层 / 技套 / 生产套管尺寸与下深 | 套管数据表、CBL 页眉 | CBL 页眉可作 B 级交叉校验 |
| 井眼尺寸 | 钻头程序、井径剖面 | 施工设计、井径图、结构图 | 钻头程序不能直接等同真实井径剖面 |
| 悬挂器与分级箍 | 悬挂器位置、分级箍位置 | 施工设计、CBL 页眉、完井报告 | 若缺失，保留空值而非猜测 |
| 评价窗口 | 测量井段、目的井段、重点评价段 | CBL 图、设计文件 | 可直接支持 `evaluation_windows` |
| 偏心相关 | 居中度/偏心度剖面 | 专项结构资料 | 当前大概率缺失 |

#### 当前已确认的 `WellSpec` 高价值样例

- 呼103回接 CBL：测量井段 11–5472 m，人工井底 5480.25 m，固井方式分级固井
- 呼103油层尾管 CBL：测量井段 15–3959 m，完钻井深 4018 m，固井方式单级固井
- 呼103回接实验报告：井深 5540.9 m，套管尺寸 193.7 mm

### 6.2 `FluidSpec` 映射口径

`FluidSpec` 负责表达钻井液、平衡液、隔离液、冲洗液、领浆、尾浆等流体的物性和角色。

| 字段类别 | 典型字段 | 主来源 | 备注 |
|---|---|---|---|
| 基础属性 | `name`, `role`, `density` | 实验报告、施工设计 | 设计值与实测值分开存 |
| 流变参数 | `rheology_model`, `n`, `K`, PV, YP | 实验报告流变表 | 优先用同井实测 |
| 配方信息 | 配方/组成、水灰比、液固比、造浆率 | 实验报告 | 适合作为注释或 provenance |
| 稳定性指标 | 自由水、稳定性、冲洗效率、失水量 | 实验报告 | 可进入诊断解释层 |
| 相容性 | 与钻井液/平衡液/隔离液混配试验结果 | 相容性实验表 | 不直接等于流变模型，但影响施工风险判断 |

#### 当前已确认的 `FluidSpec` 高价值样例

来自 `203211.docx`：

- 钻井液：密度 2.02 g/cm3，PV 47 mPa·s，初切力 3.5 Pa，终切力 7 Pa，流变表给出 `n=0.647, K=0.590`
- 驱油隔离液：密度 1.80 g/cm3，稳定性上/中/下 = 1.79 / 1.80 / 1.80，冲洗效率 97.3%，流变表给出 `n=0.587, K=0.880`
- 领浆：密度 1.90 g/cm3，稠化 493 min，API 失水 42 mL，24h 强度 11.5 MPa，`n=0.838, K=0.587`
- 尾浆：密度 1.90 g/cm3，稠化 295 min，API 失水 35 mL，24h 强度 14.7 MPa，`n=0.766, K=1.093`

### 6.3 `PumpingSchedule` 映射口径

`PumpingSchedule` 负责表达施工顺序、流体切换、体积、排量、时间与关键工艺节点。

| 字段类别 | 典型字段 | 主来源 | 备注 |
|---|---|---|---|
| 施工步骤 | step name / fluid name | 施工设计、作业史 | 优先保留中文原步骤名 |
| 体积 | `volume_m3` | 施工设计、现场总结 | 设计值与实际值双轨保存 |
| 排量 | `rate_m3_min` | 施工设计、施工记录表、施工曲线 | 若为变排量，应拆多步 |
| 时间 | `start_time_s`, `end_time_s` | 施工曲线、现场作业史 | 缺失时可后续由体积和排量反推 |
| 关键压力节点 | 碰压、井底当量、最大泵压 | 施工设计、曲线 | 主要用于校核与注释，不一定进入基础 schedule |

#### 当前已确认的 `PumpingSchedule` 高价值样例

来自 `well_spacer_summary_fixed.csv` 已核对的呼103回接设计摘要：

- 平衡液 18 m3 @ 1.75 g/cm3
- 驱油隔离液 18 m3 @ 1.80 g/cm3
- 驱油冲洗液 14 m3 @ 1.02 g/cm3
- 领浆 91 m3 @ 1.90 g/cm3
- 尾浆 19 m3 @ 1.90 g/cm3
- 主施工排量约 1.3 m3/min
- 碰压约 42–47 MPa

### 6.4 `ValidationData` 映射口径

`ValidationData` 用于保存后验验证资料，而不是用于反向校准求解器。

| 字段类别 | 典型字段 | 主来源 | 备注 |
|---|---|---|---|
| CBL/VDL 图 | 文件路径、测井日期、解释日期 | 原始 PDF | 主验证资料 |
| 解释结论 | 合格/不合格、局部评价 | PDF 页眉、解释结论栏 | 与图像一起保存 |
| 测量井段 | 起止深度 | PDF 页眉 | 直接映射评价窗口 |
| 水泥面 | 预计 / 实测 | PDF 页眉 | 重要校核字段 |
| 现场质量摘要 | 作业总结中的质量描述 | 施工总结、技术报告 | 仅作补充说明 |

#### 当前已确认的 `ValidationData` 高价值样例

- 呼103回接 CBL：固井质量“合格”，水泥面实测 38 m
- 呼103油层尾管 CBL：固井质量“合格”，水泥面实测 0 m

## 8. 缺失字段与 fallback 顺序

### 8.1 当前高概率缺失字段

目前 0708 中尚未稳定确认到以下字段的直接入口：

- 偏心环空 / 居中度剖面
- 泥饼厚度与泥饼力学参数
- 温度剖面或更完整的井温场
- 地层压力 / 破裂压力 / 窜槽风险相关参数
- 统一格式的现场施工时间轴

### 8.2 fallback 顺序

当字段缺失时，统一采用如下兜底顺序：

1. **同井、同作业阶段的原始资料**（A 级）
2. **同井、相邻资料源的明确复述**（B 级）
3. **同井不同阶段、但工程上可解释的近似值**（B/C 级）
4. **邻井同类工况**（C 级）
5. **论文或历史脚本**（C 级）

任何走到第 4、5 级的字段，都必须在提取数据文件中明确标记 `fallback`。

## 9. 当前环境限制与处理策略

### 9.1 已确认限制

- 工作区外路径对部分媒体代理不可见，导致外部路径 PDF 无法直接由子代理读取
- 本机命令行未发现 `soffice`，因此旧 `.doc` 不能依赖 LibreOffice 路径统一转 PDF

### 9.2 当前可行路径

- PDF：优先用主代理直接读取 PDF 文本和页面内容
- docx：优先用 `pandoc --extract-media` 抽正文和内嵌图片
- doc：若后续确需读取图片，应优先转换为 docx，或由用户提供可访问副本
- 图片：只把有明确图题、井号、图例的识别结果作为 B 级证据

## 12. 本设计的边界声明

本设计文档只定义“如何把资料变成标准字段”，不定义“如何重构所有 loader”。后续进入实施计划时，才会进一步拆到：

- 抽取模板先做哪些列
- 哪口井先做样板
- 哪些字段可先手工录入
- 哪些字段需要保留空值等待后补
- loader / runner 的重构顺序

换句话说，本设计文档是**资料治理设计**，不是**代码重构方案**。
