### 1.6 问题陈述（三句）

1. **判据与控制流耦合**：`cement_end_time_s` 既是"物理停止时刻"又是"控制流分支开关"，回退**静默**发生（`CasingFlowResult.notes` 有胶塞注记，但 `.notes` 字段全仓无消费点——`grep -rn "\.notes" cemdisp/` 只命中其他类的同名属性，故回退事实**不进入任何输出**）。
2. **判据落在零余量上**：三口刀锋井（ht1_004 +0.036；ht1_003 +2.0；hu103 +1.65）与五口回退井（−0.74 ~ −2.13）在数值上**紧贴边界**，任何取整/口径微调都会翻转分支。
3. **语义被用户否决**："尾缘到不了鞋就静默改算到泵注结束"（R61）不被接受；但**代码自述的物理**（`casing_flow.py:336-339`、`annulus_d2dga.py:2201-2205`）恰恰是"停泵即冻结、界面停滞"——两者需要被显式地摆在一起裁定。

## ② 候选方案

> 记号：`T_pump` = `pumping_end_time_s`（顶替序列终点，`casing_flow.py:270`）；
> `T_rear` = 尾浆尾缘过鞋时刻（`_rear_arrival_time` 的返回值，可能为 `None`）；
> `S` = 尾缘迟到量（shortfall）= `目标体积 − 总泵入体积`（`>0` 时即"未碰压"）。

### 候选 A：显式工艺停泵时刻 + 尾缘迟到量（诊断化）

**做法**：停止时刻由**外部显式给定**（如 `WellSpec` 新字段 `stop_time_s`，或"泵注结束 + 已知尾缘滞后 Δt"），
把"尾缘是否已到鞋"从**控制流判据**降级为**诊断输出**（`shortfall_m3`、`T_rear`、`arrived: bool`）。

**1) 物理依据**
- 本模型评价的是"**顶替过程结束时环空内的水泥分布**"。顶替的**驱动**是地面泵注；泵停 ⇒ 驱动消失。
  代码已按此实现：`annulus_d2dga.py:2201-2205` 停泵即冻结水泥场（gel strength <2h）。⇒ **2D 窗口的物理上界就是工艺停泵时刻**，与"尾缘是否已到鞋"无关。
- 对**未碰压**井（5 口），尾缘在泵注结束时**仍在管内**（S>0），这是**现场事实**（替浆量不足/单流阀失效），
  不是数值缺陷。显式停泵时刻 + 诊断输出**如实呈现**该事实，符合 R61 的诉求（"不接受静默改算"）。
- 对**碰压**井（3 口），工艺停泵时刻 ≈ 碰压时刻 ≥ `T_rear`。若取 `stop = T_pump`，则比现状（`T_rear`）**更长**，
  在泵注末尾（`T_rear → T_pump` 区间）**泵仍在注替浆液**，场仍在演化 ⇒ **会改变 η**（见"口径影响"）。

**2) 代码落点**
- 新增显式输入：`cemdisp/data/well_spec.py:130` 附近（`shoe_lag_volume_m3` 同族字段）新增 `stop_time_override_s: Optional[float]`（或按 A′：新增 `shoe_lag_time_s`）。
- 消费点：`casing_flow.py:320-340`（把 `None` 分支改为"写诊断、`cement_end_time_s` 取显式值"）；`casing_flow.py:56-70` `CasingFlowResult` 新增 `rear_arrived: bool` / `rear_shortfall_m3: float` / `stop_time_source: str`。
- 8 份 runner `annulus_stop_time_s()`（§①1.1 清单）改为"读显式字段，缺失才回退旧逻辑"。
- 8 份 `run_and_export` 的摘要写出点（hu101:92、hu102:56、hu103:55、hu1:70、hu2:68、ht1_001:73、ht1_003:56、ht1_004:71）新增诊断字段。
- 8 份 loader（`cemdisp/data/loaders/*_loader.py`）填新字段。

**3) 波及面**：见 §③ 表。**8/8 井全部受影响**（碰压 3 口停算延长至 `T_pump`；未碰压 5 口"来源标注"改变但数值不变）。

**4) 实现量 / 口径**
- 实现量：**中-大**（8 runner + 8 loader + 1 dataclass + 1 WellSpec + 摘要链；约 1.5-2 天 + 8 井重跑）。
- **改数值口径：是**（碰压 3 口的 `total_t` 变为 `T_pump`；未碰压 5 口数值不变但需重跑确认）。

**5) 风险**
- 碰压井延长到 `T_pump` ⇒ 末段（`T_rear`→`T_pump`）**泵仍在注替浆液** ⇒ η 会变；变多少**未取到实测**（须实跑）。
- "显式给定"的来源若仍是"泵注结束 + 人工滞后"，则该滞后值**又要一次口径裁定**（循环）。
- 与论文方法章现有的"耦合仅通过入口状态完成"表述**不冲突但需补一句**（见 §④）。

**6) 条件式**
- 若目标 = "停止时刻与'尾缘是否到鞋'**解耦**、且未碰压井如实反映滞留" ⇒ **A 满足**。
- 若目标 = "**不改动任何已有数值**（碰压 3 口保持现状 `T_rear`）" ⇒ **A 不满足**。

### 候选 B：解析外推（停泵时刻 = 泵注结束 + 尾缘到鞋的预期滞后）

**做法**：`stop = T_pump + S / q_last`（`q_last` = 末步排量 m³/min；S = 迟到量）；
即"继续算到尾缘**预期**到鞋的时刻"。碰压井 `S ≤ 0` ⇒ 退化为 `T_rear`（≈现状）。

**1) 物理依据**
- 该式**假定泵在 `T_pump` 之后继续以 `q_last` 注入**（把"未泵完的那 S m³ 补完"）。
  这是**对现场工况的假设**：现场是否"继续顶替到碰压"取决于工艺（多数尾管固井**要求碰压**，若未碰压则停泵等凝固）。
- **与代码自述物理直接冲突**：`casing_flow.py:336-339` 明写"泵停（碰压）后无顶替驱动…界面停滞"；
  `annulus_d2dga.py:2201-2205` 停泵即冻结。⇒ 即使把窗口延伸到 `T_pump + Δt`，**该时段无任何场演化**（§①1.2）。

**2) 代码落点**
- `casing_flow.py:320-343`（`None` 分支改为解析外推）；`casing_flow.py:336-339` 的钳制需同步修改或删除（否则外推值立即被钳回 `T_pump`）。
- 8 份 runner `annulus_stop_time_s()`：**可不改**（继续读 `cement_end_time_s`），但需改其语义注释。
- 8 份 loader：**不需改**。

**3) 波及面**：未碰压 5 口**全部延长** `S/q_last` 分钟（纯算术，见 §③）；碰压 3 口不变。

**4) 实现量 / 口径**
- 实现量：**小**（1 处核心逻辑 + 注释；约 0.5 天）。
- **改数值口径：是（但实质无影响）**——由 §①1.2，延长时段场已冻结，**η 逐位不变**，只多算机时。
  前提：`S/q_last ≤ 2h`（八井最大 `S/q_last` = hu2 3.55 min，远小于 2h ✓）。

**5) 风险**
