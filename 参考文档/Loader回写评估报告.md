# Loader 回写评估报告

## 1. 概述

本报告评估六口井（呼101、呼102、呼103、呼探1、呼探1-001、呼探1-002）的提取数据回写到 Loader 和 Provenance 文件的可行性。

**评估结论摘要：**
- 呼101：提取数据与 Loader 高度一致，部分流变参数存在主值/复检值差异，建议保持 Loader 不变
- 呼102：提取数据存在邻井代理问题，但现场主作业记录与 Loader 基本吻合，建议保守更新
- 呼103：提取数据部分流变参数与 Loader 差异较大，需验证后逐步更新
- 呼探1：提取数据来自呼探1-001作业史，两者在密度参数上存在差异，需核实井号
- 呼探1-001：提取数据与 Loader 基本吻合，流变参数已确认 field 级别
- 呼探1-002：提取数据与 Loader 基本吻合，密度和流变参数一致

## 4. 回写策略建议

### 4.1 保守策略（推荐）

- 保持现有 Loader 不变
- 提取数据作为参考和验证依据
- 仅在确认无误后逐步更新

**适用场景：**
- 提取数据存在两组值（如呼101主值/复检值）
- 不同来源数据存在冲突（如呼103密度差异）
- 井号混淆（如呼探1 vs 呼探1-001）

### 4.2 激进策略

- 用提取数据中的 A 级数据替换 Loader 中的代理值
- 保留原始代理值作为注释
- 批量更新 Provenance 状态

**适用场景：**
- 提取数据与 Loader 完全一致且均为 A 级证据
- 已通过交叉验证确认数据准确性

### 4.3 推荐策略

**建议采用保守策略，原因如下：**

1. **提取数据可能包含人工转录误差**：多份文件的数据应交叉验证
2. **部分数据存在两组值**：如呼101主值/复检值，需评估差异影响
3. **井号混淆问题**：呼探1与呼探1-001数据混用，需严格区分
4. **Loader 中的数据已经过验证**：部分代理值有明确注释说明

**分阶段实施方案：**

| 阶段 | 行动 | 说明 |
|------|------|------|
| 阶段1 | 核实呼103水泥浆密度 | 1.90 vs 2.05g/cm³ 差异需确认 |
| 阶段2 | 更新呼探1-002 Provenance | 平衡液/隔离液从 partial 升级 |
| 阶段3 | 更新呼探1-001 压塞液密度 | 从 1.98 改为 1.60g/cm³ |
| 阶段4 | 确认后更新呼103 Provenance | 平衡液和隔离液升级为 field |
| 阶段5 | 端到端测试验证 | 运行全部六口井模型验证 |
