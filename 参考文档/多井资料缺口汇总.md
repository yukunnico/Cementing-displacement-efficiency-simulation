# 多井资料缺口汇总

## 1. 概述

本文档汇总六口井（呼101、呼102、呼103、呼探1、呼探1-001、呼探1-002）的资料缺口，评估 fallback 策略，给出后续补录优先级建议。

### 1.1 数据结构说明

每口井的资料按四个核心数据集组织：

| 数据集 | 说明 |
|--------|------|
| WellSpec | 井身结构参数（井深、套管、尾管、井眼直径等） |
| FluidSpec | 流体物性参数（密度、流变模型、配方等） |
| PumpingSchedule | 施工时序（注入步骤、排量、压力等） |
| ValidationData | 验证数据（CBL/VDL 测井结果、水泥面实测等） |

### 1.2 证据等级定义

| 等级 | 含义 | provenance.status | 典型来源 |
|------|------|-------------------|---------|
| A | 原始正文/实测数据 | `field` | CBL 原始 PDF、实验报告流变数据、施工记录表 |
| B | 二次汇总/设计值 | `partial` | 施工设计、汇总表交叉校验 |
| C | 类比兜底/文献值 | `proxy` | 邻井代理、历史脚本占位值 |
| - | 未找到 | `unknown` | 当前缺失，需后续补录 |

## 3. Fallback 策略

### 3.1 Fallback 顺序

当字段缺失时，统一采用如下兜底顺序：

| 优先级 | 来源 | 等级 | 说明 |
|--------|------|------|------|
| 1 | 同井、同作业阶段的原始资料 | A 级 | 直接使用，明确标注来源 |
| 2 | 同井、相邻资料源的明确复述 | B 级 | 二次校验，保留来源说明 |
| 3 | 同井不同阶段、但工程上可解释的近似值 | B/C 级 | 需标注近似原因 |
| 4 | 邻井同类工况 | C 级 | 仅在缺失时兜底，不可覆盖 A/B |
| 5 | 论文或历史脚本 | C 级 | 最终兜底，需标注"代理值" |

### 3.2 各井 Fallback 评估

#### 呼103

| 缺失字段 | 推荐 fallback 策略 | 替代方案 |
